# Речка и Песок - Telegram Bot для автоматизации предзаезда

Полностью рабочий прототип Telegram-бота для автоматизации предзаезда гостей на турбазу "Речка и Песок" (г. Волгоград).

## Технологический стек

- **Python 3.11+**
- **aiogram 3.x** - Telegram Bot framework
- **FastAPI** - Admin panel API
- **PostgreSQL/SQLAlchemy 2.0** - Database
- **Docker & Docker Compose** - Containerization
- **OpenAI API** - LLM integration for parsing free-form responses

## Установка и запуск

### 1. Клонирование и настройка

```bash
# Скопировать проект
cd AI_agent

# Создать файл конфигурации
cp .env.example .env

# Отредактировать .env с вашими токенами
# BOT_TOKEN=your_telegram_bot_token
# DATABASE_URL=postgresql+asyncpg://rechkapesok:rechkapesok_password@localhost:5432/rechkapesok
# OPENAI_API_KEY=your_openai_api_key
# ADMIN_IDS=123456789,987654321
```

### 2. Запуск с Docker (рекомендуется)

```bash
# Запустить все сервисы
docker-compose up -d

# Инициализировать базу данных
docker-compose exec bot python -m src.init_db

# Проверить логи
docker-compose logs -f bot
```

### 3. Локальный запуск (без Docker)

```bash
# Установить зависимости
pip install -r requirements.txt

# Настроить PostgreSQL (убедитесь, что база данных создана)
# Создать базу данных: createdb rechkapesok

# Инициализировать базу данных
python run_init_db.py

# Запустить бота
python run_bot.py

# Запустить админ-панель (в отдельном терминале)
python run_admin.py
```

## Основные функции

### 1. Запуск бота

Гости запускают бота командой:
```
/start <token>
```

Где `<token>` - это токен из брони (например, `DEMO-ONLY-R001`).

### 2. Сбор информации

Бот собирает следующую информацию:
- Количество взрослых и детей
- Время прибытия (формат ЧЧ:ММ)
- Наличие автомобиля и госномер
- Наличие питомца
- Дополнительные услуги (доп. место, ранний заезд, завтрак)
- Принятие правил

### 3. Валидация и безопасность

- **Токен-аутентификация**: Бот работает только с валидными токенами
- **Валидация времени**: Проверка формата ЧЧ:ММ
- **Валидация госномера**: Минимум 6 символов
- **Эскалация**: Вопросы вне компетенции передаются администратору

### 4. Расчет доплат

Расчет доплат производится на основе `prices.json`:
- Питомец: 1500р за ночь
- Уголь: 500р за упаковку
- Ранний заезд: цена по запросу администратора

### 5. Формирование КПП

Строка для КПП формируется автоматически при `has_car=true`:
```
booking_id, arrival_date, arrival_time, house_id, car_plate
```

### 6. Напоминания

Система напоминаний отправляет уведомления через 12 часов после создания брони (максимум 1 напоминание), затем переводит статус в `needs_human`.

### 7. Админ-панель

FastAPI админ-панель доступна на `http://localhost:8000` с мобильной таблицей бронирований.

## Тестирование сценариев

Проект включает 10 тестовых сценариев из `tests.json`:

1. **R01**: Полная карточка с питомцем и автомобилем
2. **R02**: Карточка без автомобиля, измененное количество гостей
3. **R03**: Валидация некорректного времени и госномера
4. **R04**: Вопрос о фейерверках (эскалация)
5. **R05**: Запрос на изменение дат (эскалация)
6. **R06**: Отказ от правил (эскалация)
7. **R07**: Тест напоминаний (12 часов)
8. **R08**: Неверный токен (ошибка безопасности)
9. **R09**: Запрос угля и раннего заезда
10. **R10**: Полная карточка без машины, запрос человека

### Команда для тестирования времени

Для тестирования сценария R07 (напоминания) используйте команду:

```
/travel_time <hours>
```

Эта команда сдвигает системное время вперед для демонстрации работы напоминаний.

## Статусы карточек

- **ready**: Все поля заполнены, правила приняты
- **incomplete**: Не хватает информации
- **needs_human**: Требуется вмешательство администратора
- **confirmed**: Подтверждено администратором

## Правила безопасности

1. **Приватность**: Бот не раскрывает информацию о чужих бронированиях
2. **Токены**: Работа только с валидными токенами
3. **Эскалация**: Вопросы о штрафах, правилах и изменениях передаются администратору
4. **Оплата**: Информация об оплате выводится с примечанием "Оплата производится строго на ресепшене при заселении"

## Файлы данных

- `bookings.json`: Данные бронирований

- `faq.json`: Часто задаваемые вопросы
- `tests.json`: Тестовые сценарии
- `dialogues.json`: Диалоги для тестирования
